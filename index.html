Engineering & hardware

Final-year capstone

AIUB, Faculty of Engineering Role: sensing, control & firmware Status: built and defended

HydroSense — IoT smart irrigation system

An automated irrigation controller for small farms. Soil moisture and flow sensors feed an ESP32, which drives the pump zone by zone instead of running on a fixed timer. It reports over GSM so it works on land with no Wi‑Fi, and the interface is a bilingual progressive web app — a farmer can use it on a low-end phone with a weak connection.

  • Designed the sensing and control side — soil moisture and flow sensor integration, relay-driven pump control, and the zone logic that decides when to water.
  • Wrote the ESP32 firmware and dealt with the electrical problems that only appear once a real pump is attached, including separating the pump supply from the control electronics so the board stopped resetting on pump start-up.
  • Taught myself progressive web app development from scratch — offline caching, an installable interface, and a bilingual layout for users who don’t read English. None of that is in an EEE syllabus.
  • Wrote the capstone defence book documenting the design decisions, the test results, and the reasoning behind each one.

Team project · Group 2026.2.7

AIUB  ·  four members Role: embedded & data pipeline Prototype tested 19–27 Jul 2026

Hybrid solar–grid fast charging system with AI diagnostics

A charging system that draws from solar first and falls back to the grid, with MPPT tracking, a smart battery management layer for protection, and a machine learning pipeline that flags faults from live sensor data. An ESP32 acts as the edge node; a Raspberry Pi Zero 2 W runs the server and the model. Built as a working prototype, then written up as a six-chapter project book.

  • Built the embedded side — ESP32 firmware split into sensing, control, display and network modules, reporting to the Raspberry Pi server.
  • Owned the diagnostics dataset — 302,915 raw samples cleaned down to 301,696 usable ones, working through each cleaning decision rather than accepting the raw log as it came.
  • Compared simulated behaviour against measured hardware and documented where the two disagreed and why, instead of reporting only the runs that matched.
  • Produced the documentation — the six-chapter book, appendices of IC datasheets and source code, and a condensed IEEE-format summary paper drawn from it. Cleared plagiarism screening at 8% similarity with no integrity flags.

Course project · Renewable Energy Technology

AIUB  ·  group Role: modelling & sizing Output: IEEE-format report

Off-grid solar PV system design and simulation for Bangladesh

A full sizing and simulation study for a standalone solar installation under Bangladeshi irradiance and load conditions, ending in a 2S × 4P eight-module array configuration. The work covered load estimation, panel and battery sizing, and modelling how the system would behave before any of it was built.

  • Modelled the array in MATLAB and Simulink and produced the I–V and P–V characteristics used to justify the chosen configuration.
  • Worked the sizing calculations by hand first — irradiance, module output, series and parallel arrangement — so the simulation was checking my reasoning rather than replacing it.
  • Wrote it up in IEEE format, which meant stating assumptions explicitly and citing a source for every figure I hadn’t measured myself.

Undergraduate thesis

AIUB  ·  group research Role: dataset evaluation & method design Status: in progress

Effect of colour and layout on user attention in web interfaces

A study of how visual design choices change where people actually look on a web page. Much of the work was evaluating existing eye-tracking and saliency datasets against our requirements, then designing our own experiments for the parts no dataset covered.

  • Evaluated published eye-tracking and saliency datasets — UEyes, Imp1k, FiWI — comparing what each one measured against what the study needed. That is a requirements-matching exercise before it is a research one.
  • Helped design the experiments for the gaps: A/B testing, five-second memory tests, blur tests, distraction tests and side-by-side ranking.
  • Worked in a field with no electrical engineering content at all, which meant reading unfamiliar literature and learning another discipline’s vocabulary before I could contribute anything.
